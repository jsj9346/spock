```

2024-01-31    0.05    0.05   ... 0.05  ← 리밸런싱 날

2024-03-01    0.00    0.00   ... 0.00  ← 다시 청산!
```

이 패턴이 11번 반복되어 실제 포지션 유지 기간은 **11일뿐**이었습니다.

#### 2. 코드 문제점 식별

**[backtest_three_factor_strategy.py:150-177](../examples/backtest_three_factor_strategy.py#L150-L177)**

```python
# 문제 있는 코드
weights_df = pd.DataFrame(
    0.0,  # ← 문제: 0.0으로 초기화 (NaN이 아님)
    index=price_df.index,
    columns=price_df.columns
)

# 리밸런싱 날에만 가중치 설정
for rebal_date, group in signals_df.groupby('date'):
    weights_df.loc[closest_date, ticker] = weight
```

**원인**: `fillna()`는 `NaN` 값만 forward-fill하는데, `0.0`으로 초기화했기 때문에 forward-fill이 적용되지 않음.

#### 3. 실제 영향

- **포트폴리오 유지 기간**: 11일 (전체 224 거래일 중 4.9%)
- **실제 거래**: 11번 매수 + 11번 매도 = 22번 왕복 거래
- **총 거래비용**: ~4.4% (11번 왕복 × 0.4% 거래비용)
- **순손실**: -0.21%

### 수정 방안

**[backtest_three_factor_strategy.py:130-203](../examples/backtest_three_factor_strategy.py#L130-L203)**

```python
# 수정된 코드
weights_df = pd.DataFrame(
    np.nan,  # ✅ NaN으로 초기화
    index=price_df.index,
    columns=price_df.columns
)

# 리밸런싱 날짜들을 정렬
rebal_dates = sorted(signals_df['date'].unique())

# 각 리밸런싱 기간에 대해
for i, rebal_date in enumerate(rebal_dates):
    # 시작일 찾기
    start_date = matching_dates[0]

    # 종료일 결정 (다음 리밸런싱 전날 또는 마지막 날)
    if i < len(rebal_dates) - 1:
        end_date = price_df.index[price_df.index < next_rebal][-1]
    else:
        end_date = price_df.index[-1]

    # 전체 기간에 가중치 적용
    date_mask = (weights_df.index >= start_date) & (weights_df.index <= end_date)
    weights_df.loc[date_mask, ticker] = weight

# 남은 NaN을 0.0으로 채우기 (백테스트 시작 전)
weights_df = weights_df.fillna(0.0)
```

**핵심 개선사항**:
1. 초기화를 `np.nan`으로 변경
2. 리밸런싱 날짜들을 정렬하고 시작일~종료일 명시적 계산
3. 각 기간 전체에 가중치 적용 (`date_mask` 사용)
4. 로깅 개선 (리밸런싱 기간 표시)

### 주요 교훈
1. **철저한 검증의 중요성**: 데이터 파일 분석으로 버그 발견
2. **거래비용의 압도적 영향**: 수익의 95%를 잠식
